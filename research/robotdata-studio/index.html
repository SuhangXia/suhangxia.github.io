Independent software · Robot data infrastructure

RobotData Studio

From collected files to an inspectable data asset.

Robot demonstrations carry more than actions: sensor timing, calibration, processing history and decisions about what to train on. RobotData Studio brings these records into one local workspace, while a browser demo makes a fixed public catalog directly queryable.

DuckDB-Wasm

The local application registers read-only sources, scans fields and timing, records review history, and freezes catalog or selection manifests. SQLite tracks operational state; immutable Parquet snapshots hold analytical results. Spark performs batch joins and aggregates; DuckDB handles interactive queries.

The public demo shares the React workspace and queries exported Parquet in a Web Worker. Visitors can filter episodes, inspect physical field meanings and quality findings, follow artifact bindings, and download a personal selection draft. It runs without a connection to the collection computer.

Connected to actual robot data.

The current catalog contains 475 logical episodes across Tactile UMI insertion demonstrations and a DROID LeRobot v3 export. Raw H5, aligned H5 and training Zarr remain linked representations of the same UMI episodes. Imported historical analyses are distinguished from checks executed by this software.

Methods and current boundaries

Six Spark SQL recipes were compared against DuckDB on the real snapshot. Timestamp diagnostics, mapped-age intervals and source-frame reuse describe observable data conditions, not task success or labeling accuracy. Full media decoding remains unrun unless explicitly performed. Frozen manifests preserve selection and provenance; they are not complete LeRobot or Zarr training-data conversions.

RobotData Studio is independent of Tactile UMI, UniForce and Diffusion Policy. Existing Quest and camera latency work follows the credited exUMI method; this catalog does not claim that method as a contribution.
